## Candidate scope

ACE 1.1 Code Intelligence adds a bounded, read-only repository-to-reasoning journey for
architecture, symbols, tests, calibrated downstream impact, provenance, omissions, and uncertainty.
Governed admission, resource queries, Atrium, and later use retain exact repository snapshot
identity. The supported external-agent handoff is body-free and bounded; it transfers neither
repository content nor execution, network, provider, persistence, delivery, or effect authority.

Delegated headless review and activation require an exact product, SERVICE principal, capability,
and pre-existing grants. Review and activation remain separate, replay remains exact across
restart, and revocation denies current use without rewriting history. The public MCP boundary
remains exactly eleven tools.

The candidate also contains the nine-item release hardening and upgrade packet: product-scoped
operational-relationship reads, explicit orchestration-run product identity, configured-product
Sentinel startup and typed SurrealDB record identifiers, provider/runtime fail-closed behavior,
SurrealDB 3.2 preparation, schema-v179 recovery guidance, assertion-history upgrade controls,
backup/restore commands, operations-document packaging, archive integrity, and Atrium navigation
identity/accessibility corrections. These are bounded hardening changes, not authority or topology
expansion.

## Compatibility, migration, and rollback

- Runtime support remains Python 3.12 and the documented single-node topology with SurrealDB 3.2.
- The packaged schema head is v179. Operators must take and verify a backup before upgrade, run the
  documented dry-run/inventory steps, apply only reviewed mappings, retain quarantine and receipts,
  and prove restart behavior.
- Rollback means restoring the verified pre-upgrade backup; no downgrade-in-place claim is made.
- The reference workspace-action adapter remains distribution 0.4.1 with unchanged executable
  implementation identity 0.1.0. Only its declared Core envelope widens to
  `ace-core>=0.8.0,<1.2`; installation grants no operation authority.
- This release does not claim collaboration, managed hosting, universal connectors, distributed
  availability, universal language support, safe-deletion proof, hostile-code isolation, or
  autonomous policy application.

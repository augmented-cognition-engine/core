# ACE 1.2.1 public acceptance — draft summary (J1–J10)

Run: 2026-08-20, ~08:23–08:50 PDT, single session. Runner: fresh-eyes agent as a first-time
user, public artifacts only (GitHub release v1.2.1 + PyPI `ace-core==1.2.1` + public docs
rendered on GitHub; no source checkout). Full evidence: `RUN_LOG.md` in this directory.

## Verdict

**ACE 1.2.1 does not pass the Personal Intelligence public acceptance journey.** The journey
fails at its second step exactly as 1.2.0 did, one layer deeper: 1.2.1 shipped the missing
build *planner*, but (a) the planner never loads from the published artifacts because of an
entry-point loading bug, and (b) even with that bug locally patched, the journey dead-ends
because no build *executor*, no local-source acquisition implementation, no
folder-authorization surface, and no Personal Intelligence UI exist in any published artifact.
The release's own headline claim — "`builds/prepare` now plans the journey from public
artifacts" — is false as shipped. The substrate that does exist (governance, receipts,
fail-closed boundaries, ownership/export/deletion) behaved impressively and honestly.

## Deviations and interventions

- **D1:** `uv pip install ace-core==1.2.1` failed ~1h after publish (index cache); `--refresh`
  fixed it. Not documented.
- **D2:** Journey driven via the public authenticated HTTP API instead of the Atrium browser
  UI (headless runner). Moot for J3+ — the packaged Atrium has no Personal journey either.
- **W1:** One-line venv patch to `intelligence_build_planner_registry.py` (invoke factory
  functions), applied ONLY after recording J2 as FAIL, to let later steps be evaluated.
  Original and patched sha256 in RUN_LOG. No file outside `~/ace-121-acceptance/` touched.
- **D3:** Ownership grant refs (`authority_grant:personal-export` / `personal-delete`) are
  undocumented; discovered by reading installed code.

## Defect register (details in RUN_LOG)

- **F1** `ace setup` deterministic false-failure "local-owner permission verification was
  incomplete" on healthy package-only installs; onboarding evidence records setup as failed.
- **F2** `ace doctor` probes SurrealDB on a hardcoded default (foreign instance on this host)
  instead of the configured isolated port; passed checks against the wrong database.
- **F3** (release-blocking) Planner entry point never loads: registry invokes only class
  targets; shipped target is a factory function → every `builds/prepare` 503.
- **F4** All registry errors surface as "planners are ambiguous", masking root cause.
- **F5** No implementation of `ace.source.snapshot/v1alpha1` in any public artifact.
- **F6** Acquisition port and change-diff primitives ship uncalled; adapters imported by nothing.
- **F7** No API surface to name a folder or record a local-source selection.
- **F8** Packaged Atrium contains no Personal Intelligence journey.
- **F9** Pack source-mapping covers Markdown only; profile advertises md+pdf+csv+json.
- **F10** (release-blocking) `ace.intelligence_builders` executor entry-point group is empty;
  `builds/start` cannot execute any profile.

## Known limitations of this run

- J3–J10 conclusions are from a runtime carrying W1; pristine-artifact behavior for those
  steps is strictly worse (everything 503s at prepare).
- J9/J10 were exercised over a minimal record set (no briefs/revisions/corrections existed).
- The four-record reconciliation (tag / PyPI / release page / evidence) was not in scope here
  beyond what installation itself verified.

## What 1.2.2 (or a re-cut) must fix before rerunning

1. Invoke non-class planner entry-point targets (F3) — and surface registry root causes (F4).
2. Ship a Personal Intelligence build executor registered in `ace.intelligence_builders` (F10).
3. Ship the local-source acquisition host service implementing `ace.source.snapshot/v1alpha1`,
   wired to the four adapters, with a selection-recording surface that shows exact folder
   scope, read-only mode, and expected contribution before any read (F5–F7).
4. Ship the Personal journey UI or an equivalent documented CLI path (F8), complete pack
   mappings for PDF/CSV/JSON (F9), and make the release smoke gate exercise
   prepare→bind→approve→start→first-Brief from installed artifacts, not from a checkout.
5. Fix F1/F2 and document the ownership grant refs (D3).

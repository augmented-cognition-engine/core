**Choose → `POST /v1/intelligence/builds/prepare` (08:32:33).** Well-formed v1alpha2 request
(profile id + current digest, subject, outcome, source group, cadence `on_change`) →
**HTTP 503 `{"detail": "installed Intelligence build planners are ambiguous"}`.**

**Root cause (established from the installed artifacts themselves, no source checkout).**
- The venv has exactly ONE `ace.intelligence_build_planners` entry point:
  `personal_intelligence -> core.engine.personal_intelligence.build_planner:load_personal_intelligence_build_planner`
  (dist ace-core). Nothing is ambiguous.
- Reproduced in-process: `load_installed_intelligence_build_planners()` raises
  `IntelligenceBuildPlannerRegistryError: invalid Intelligence build profile id`.
- `core/engine/core/intelligence_build_planner_registry.py` line ~68:
  `planner = loaded() if isinstance(loaded, type) else loaded` — the factory is only invoked
  when the entry-point target is a *class*. The shipped target
  `load_personal_intelligence_build_planner` is a plain *function* returning
  `PersonalIntelligenceBuildPlanner`; the raw function is registered as the planner, has no
  `profile_id` attribute → registry rejects it fail-closed.
- **Defect F3 (release-blocking as shipped):** the first-party planner that 1.2.1 exists to ship
  (issue #252; its own module docstring says so) never loads from the public artifacts; every
  `builds/prepare` fails 503 and the Personal Intelligence journey cannot start. The 1.2.1
  release gate ("the built artifacts must start the journey or the release fails") evidently did
  not exercise this path end-to-end through entry-point loading.
- **Defect F4 (diagnostics):** the HTTP layer maps every registry error to
  "installed Intelligence build planners are ambiguous", masking the real error
  ("invalid Intelligence build profile id" ← factory-not-invoked). A user cannot tell what is
  wrong from the API response.

**Workaround W1 (recorded, minimal, fully disclosed).** To evaluate J3–J10 at all, one line of
the installed venv copy of `intelligence_build_planner_registry.py` is patched so a callable
non-class entry-point target lacking `prepare` is invoked as a factory. Original file sha256
`1ced8dfa39725f4df49868c4082e0c2b60a0021d70cba701d5726e5b894bd015` (backup:
`registry_original_backup.py`); patched file sha256
`095c7ce0d6a48a02a70cbcb829e314b1d7441245f75b2b0d549723fcbbd8d6f8`. Service restarted at
08:35:08 to load it (setup's F1 error message reappeared on restart, again cosmetic). Every
downstream step result is marked "under W1" and cannot count as evidence that pristine 1.2.1
artifacts pass. J2 itself remains **FAIL as shipped**.

**Prepare under W1 (08:35:29).** `builds/prepare` → 200 with a complete
`ace.application.intelligence-build-plan/v1alpha3` review plan (`j2_prepare_response.json`):

  `local_source_snapshot`) and authority `source_read` (request `local_source_read`). The

  contains a governed acquisition port `ace/application/local_source_acquisition.py`
  (walks an authorized folder read-only, enforces scope, digests bytes) and a pure change
  detector `ace/application/local_source_change.py` (docstring: "the pure detection primitive
  for J6's append-only revision"). Callers in `core/` (the actual API/worker host): **zero**.
  The four adapter distributions are pure parsers ("By design this adapter does not walk
  folders, read files…" per their own READMEs) and are imported by nothing.
- **F7 — no API surface accepts a folder path or records a local-source selection.** The
  prepare/bind/start schemas contain no field for a path or scope;
  `recorded_source_selections` stays empty and nothing can create one for a local folder.
- **F8 — the packaged Atrium UI has no Personal Intelligence journey.** The Atrium bundle
  (`core/engine/atrium/static/assets/index-*.js`) contains zero occurrences of
  "Personal Intelligence" and no folder-authorization flow.
- **F9 — pack maps only Markdown.** `modules/source_mapping.json` carries ONE mapping
  (`local_markdown_note`); the onboarding profile advertises markdown+pdf+csv+json source
  types. PDF/CSV/JSON have no mapping even at the declarative level.

**Governed-boundary probes (recorded, deliberate):**
- Bind with empty bindings (08:42) → 409 "reviewed activation bindings failed closed". Correct

  `approval:intelligence-activation:33b8913b…`, disposition "approved", plus a ready-made
  start_request.
- `builds/start` (08:44:33) → **503 "no Intelligence build executor is registered for profile:
  intelligence_onboarding_profile:personal"**.
- **F10 — the executor entry-point group is empty in every public artifact.** The registry

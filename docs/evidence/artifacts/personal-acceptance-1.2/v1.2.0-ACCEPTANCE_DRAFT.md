# ACE 1.2.0 public acceptance run — draft summary

Run date: 2026-08-20 (13:42–14:09 UTC). Runner: clean-user session per the frozen RUN_BRIEF.md,
public artifacts only, no repository clone, workspace `~/ace-12-acceptance/` only.
Full evidence: `RUN_LOG.md` (step-by-step, timestamps, digests, exact errors) and `runtime-logs/`.

## Overall verdict

**The ACE 1.2.0 public release does NOT pass the J1–J10 journey as published.** Installation,
artifact integrity, and the governed substrate (auth, receipts, honest refusal, restart
continuity, export/deletion) are genuinely strong. But the Personal Intelligence journey itself —
Choose → Connect → Brief — is not executable by a first-time user from public artifacts: two
required components (an onboarding profile and an Intelligence build planner) are missing from
every published artifact, and no public documentation describes any alternative path. J3–J6 and
the cited halves of J7/J8 are therefore blocked, and every result after J2 depends on one
locally-authored non-public artifact (disclosed as W3).

## Deviations, failures, and interventions (index into RUN_LOG.md)

- **D1** Getting-started docs at v1.2.0 describe the 1.0.3 install; the only documented full-runtime path requires a source checkout, which public acceptance forbids.
- **D2** README labels ace-core 1.2.0 as "the bounded ACE 1.1 Code Intelligence release" in one sentence.
- **F1/W1** Fresh package-only install: every `ace` command (including `setup` and `--help`) crashes with a pydantic traceback until a `.env` with JWT_SECRET exists; the template that setup is meant to fill is only discoverable inside the wheel. Chicken-and-egg on the bootstrap command.
- **F2/I1/W2** `ace setup` hardcodes API port 3000 and default DB port 8001 with no isolation defaults: on this host it silently attached to a pre-existing developer ACE stack, applied schema migrations v178–v179 to that database, wrote runtime assets into `~/.ace/`, and mis-identified the foreign API as "ACE already running" before 401-failing. Disclosed for reconciliation; the run then isolated everything (own config dir, DB on 18041, API on 13000 via the documented manual uvicorn path).
- **F3/W3** No public artifact ships an `onboarding_profile.json`; `catalog/profiles` is empty and Atrium's Choose flow has nothing to offer. Bridged with a locally-authored, contract-validated profile wheel (sha256 c6d432a6…, kept in `artifacts-local/`) — a non-public artifact that taints strict acceptance from J2 onward.
- **F4** No public artifact registers or implements an Intelligence build planner (`ace.intelligence_build_planners` entry-point group is empty); the Connect/Map/Watch plan can never be produced. This is the hard release gap; it was not bridged (doing so would test the runner's code, not ACE).
- **O1–O3** Catalog contains only Personal Intelligence; the pack's source mapping covers only Markdown notes (PDF/CSV/JSON adapters ship unmapped); the background worker probe reports down under the package-only launch while doctor reports ready.

## Known limitations observed (matching the release's own disclosures)

No runnable restore from export (stated in artifact and honored); deletion verifies the primary
immutable-record store only, with backups/exports/external copies explicitly excluded and
disclosed; single-node topology. These disclosures were accurate in every response inspected.

## What the release must add for a passing public J1–J10

1. Ship (or document how to obtain) the Personal Intelligence onboarding profile and a registered
   build planner in public artifacts — without these the journey cannot start.
2. A package-only runtime path: `ace setup` must run on a fresh install (no `.env` prerequisite),
   support port/config isolation, and never adopt a foreign SurrealDB/API it finds on default ports.
3. Getting-started documentation updated to 1.2.0 with a checkout-free path, plus any public doc
   for the J3–J10 user surfaces (source authorization, inventory, corrections, ownership).
